I'm a software engineer with a product mindset. I build practical tools that solve real problems, especially where technology meets people and process.

By day I'm a Senior Data Migration Consultant at Syniti, working in the enterprise data space. Outside of work I build software for the volunteer teams at my church, **HICC**, and I'm refining how I build with AI along the way.

## 🚧 What I'm working on

### Tools for church volunteer teams

Small, mobile-friendly web apps that replace group-chat threads and hand-edited documents with something clear and fair.

| Project | What it does | Status |
| --- | --- | --- |
| [**heritage-media-availability**](https://github.com/skyebrownh/heritage-media-availability) | Media team volunteers submit the days they can't serve each month, with no login. An admin sees every response in one place. | Launching to the full team in late October 2026 |
| [**heritage-media-scheduler**](https://github.com/skyebrownh/heritage-media-scheduler) | Builds the monthly media schedule from a rulebook, a roster and the team's availability, then checks the result. | In development |
| [**hicc-choir-ops**](https://github.com/skyebrownh/hicc-choir-ops) | Roster, attendance and weekly song-set planning for the choir. | Spec stage |

**Stack:** Python · Django · PostgreSQL · Tailwind CSS · deployed on Railway

### How I build: [claude-skills](https://github.com/skyebrownh/claude-skills)

My personal set of Claude Code skills. Every change starts as a GitHub issue, gets an approved plan, is built test-first, gets a fresh-context review, and is handed over with test results and manual steps before it ships. The repo holds that workflow so I can set it up in a new project in minutes.
